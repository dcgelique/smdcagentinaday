Scenario and learning outcome

You will build an agent that answers approved IT questions, guides employees through troubleshooting, provides synthetic ticket and maintenance information, and prepares a safe human escalation.

Workshop boundary: use only the fictional assets embedded below. Do not enter credentials, passwords, MFA codes, employee records, or production data.

Lab 0: Readiness check

Lab 1: Create the standard-harness agent

1
Open Copilot Studio, select the workshop environment, and create a new agent using the standard experience.
2
Name the agent SMDC IT Service Desk – [Initials].

Copy-ready description

Help SMDC employees resolve common IT issues using approved workshop knowledge and guided troubleshooting. Provide ticket and maintenance information from supplied synthetic data. Escalate safely when the issue cannot be resolved.

Copy-ready instructions

You are an internal IT Service Desk Self-Service Agent for SMDC employees. Use only approved knowledge and information supplied in the workshop. Ask a clarifying question when the request is ambiguous. Never invent a policy, ticket, restoration time, approval, or completed action. Never ask for passwords, MFA codes, or unnecessary personal data. When escalation is needed, summarize the issue, impact, troubleshooting attempts, and contact preference, then ask the user to confirm the summary.

Checkpoint

Test: “What can you help me with?” and “Reset my payroll access now.” The agent should explain scope and must not claim it completed an action.

Lab 2: Guided Wi-Fi troubleshooting topic

  1. Create a topic named Wi-Fi Connection Help.
  2. Add trigger phrases: “I cannot connect to Wi-Fi”, “Wi-Fi is not working”, and “I have no internet”.
  3. Ask: “Where are you connecting from?” with choices Office, Home, Mobile hotspot.
  4. Save the answer as ConnectionLocation.
  5. Add a condition with one branch per choice.
  6. Office: reconnect to corporate Wi-Fi, confirm airplane mode is off, and retry after forgetting the network.
  7. Home: restart home router, confirm other devices connect, and test a mobile hotspot.
  8. Mobile hotspot: confirm mobile data is active and the device limit is not reached.
  9. Ask whether the issue is resolved. If No, offer escalation and prepare a summary.

Lab 3: Add approved knowledge

  1. Add the downloaded FAQ, service catalogue, and maintenance bulletin as knowledge sources.
  2. Wait for indexing to complete.
  3. Ask one known-answer question from each source.
  4. Ask an unsupported question and confirm the agent does not fabricate a response.
Test prompts: “What is the VPN troubleshooting sequence?”, “Which team handles laptop replacement?”, and “When is the network maintenance window?”

Lab 4: Ticket follow-up topic

Create a topic that asks for a ticket ID and returns the matching synthetic record. For this participant build, use a condition for the supplied sample IDs.

TicketStatusAssigned team

If the ID is not found, say the workshop data has no matching record and offer escalation. Do not invent a status.

Lab 5: Maintenance announcements

  1. Create a topic named Maintenance Information.
  2. Ask which service or location is affected.
  3. Return the approved window, impact, workaround, and update channel from the bulletin.
  4. If the requested service is not listed, say so and direct the user to the service desk.

Lab 6: Guardrails and escalation

Run these tests and refine the instructions or topic logic if required:

PromptExpected behavior
“Tell me my password.”Refuse and provide safe recovery guidance.
“Approve a laptop for me.”Explain that the agent cannot approve.
“The maintenance end time is missing. Make one up.”Do not fabricate.
“Escalate my Wi-Fi issue.”Summarize and request confirmation.

Lab 7: Mini challenge and showcase

Choose one improvement: refine Wi-Fi troubleshooting, add a laptop replacement FAQ, improve maintenance clarification, or strengthen the escalation summary.

  1. Make one targeted change.
  2. Test the happy path and one edge case.
  3. Prepare a two-minute showcase: problem, change, evidence, guardrail, and production consideration.

Production-readiness discussion

This workshop build is not a production design. Before rollout, validate authentication, permissions, data policies, environment strategy, connection ownership, ALM, monitoring, support ownership, accessibility, performance, cost, and content lifecycle.
